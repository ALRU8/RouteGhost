# RouteGhost × Organic Maps — интеграционный проект

Это **не APK** и не копия исходников Organic Maps. ZIP содержит интеграцию в официальное приложение Organic Maps, которую GitHub Actions накладывает на исходный код, собирая форк. Установка Android Studio пользователю не нужна.

## Что реализовано

- Весь картографический интерфейс, поиск, автомобильная, пешеходная и транспортная маршрутизация — из исходного Organic Maps.
- На карте появляется кнопка **GPS** (справа внизу). Если маршрут построен и выбран, кнопка берёт точки маршрута из `Framework.nativeGetRouteJunctionPoints(12.0)` и сохраняет локально. При пустой геометрии не выдумывает трек.
- Контрольная панель содержит **Маршрут**, **Одна точка**, **Свой маршрут**.
- Импорт GPX и GeoJSON, ручное задание списка координат и типа каждого участка.
- Имитация задержек, скоростей и пробок в виде вероятностной модели, основанной на имеющейся геометрии. Симуляция обновляется раз в секунду.
- Системный Android Mock Location через `LocationManager`, foreground service и управление из уведомления.

## Ограничения

**Organic Maps — офлайн-движок.** Нужные карты региона должны быть скачаны средствами самого Organic Maps (как обычно в приложении). Его нельзя без переделки ядра превратить в онлайн-маршрутизатор без карт. В RouteGhost отдельного меню скачивания не добавлено.

Поддержка маршрутов общественного транспорта зависит от реального покрытия Organic Maps. Модель событий **не знает текущие фазы светофоров, реальные пробки и точное время прибытия автобуса**. Профиль `Transit` содержит шаги метро, автобусов и т.д., но сейчас в RouteGhost при снятии геометрии определяется преобладающий вид транспорта; **точные границы пеших отрезков и всех пересадок не восстановлены**. При временно недоступной геометрии RouteGhost несколько раз повторит попытку. Нативный патч также пытается прочитать вершины выбранного варианта из `RoutesResult`. Если Organic Maps не хранит путь с полноценными координатами, RouteGhost не будет подменять его прямой линией; воспользуйтесь GPX или собственным маршрутом. Не следует считать, что все транспортные поездки воспроизводятся точно.

При ручном маршруте между заданными точками используются прямые отрезки. Чтобы идти по настоящей дороге, сначала постройте маршрут в Organic Maps.

**Облачная сборка Органик Maps тяжёлая:** официальный проект рекомендует порядка 30 ГБ свободного места, а бесплатный GitHub-hosted runner может иметь меньше. Workflow является подготовленным сценарием, **полная сборка не проверена** на hosted runner в текущей среде. В случае нехватки диска потребуется более просторный runner или собственная машина.

## Получение APK без Android Studio

1. Создайте **новый пустой репозиторий** GitHub, не смешивая его с репозиторием старого RouteGhost 1.2.
2. Загрузите **содержимое** данного ZIP (папку `.github` нужно сохранить).
3. Откройте **Actions → Build RouteGhost (Organic Maps) → Run workflow**.
4. После успешного завершения скачайте артефакт `RouteGhost-OrganicMaps-APK`.
5. Установите APK и разрешите Android установку из выбранного источника. В настройках разработчика выберите установленное приложение как **Mock Location app**.

Для обновления исходной версии Organic Maps измените тег в `.github/workflows/build-android.yml`. Изменение upstream может потребовать адаптации `apply_patch.py`.

## Использование

**Маршрут:** в Organic Maps выбираете маршрут и вариант, нажимаете зелёную кнопку `GPS`, затем `Начать GPS`. Движок RouteGhost использует реальную геометрию, если нативная функция вернула точки. Если точек нет, отображает ошибку, не соединяет пункты прямой.

**Одна точка:** GPS → Одна точка → широта/долгота → Начать GPS.

**Свой маршрут:** GPS → Свой → импорт GPX/GeoJSON либо список координат (по одной строке `широта, долгота, MODE`). `MODE`: WALK, CAR, BUS, METRO, TRAM, TROLLEY, ELECTROBUS, TRAIN и др.

Для выключения: кнопка **Стоп** или **Стоп** в системном уведомлении.

## Исправление GitHub Actions (manifest labels)
В версии Organic Maps `2026.11.11-39-android` атрибут `android:label="@string/app_name"` встречается дважды: у `<application>` и у запускающего `<activity-alias>`. Скрипт `apply_patch.py` теперь меняет каждую метку в конкретном элементе, не выполняя глобальную замену.

## Исправление извлечения геометрии (v2.1)

`apply_patch.py` обновляет JNI `nativeGetRouteJunctionPoints` в привязанной версии Organic Maps: если геометрия из состояния активной навигации временно не доступна, приложение пробует вершины сохранённого **выбранного** маршрута (`RoutingSession.RouteCall` / `RoutesResult.GetActive().ForEachPoint`). Это не внешняя маршрутизация и не прямая от старта к финишу.

Кнопка GPS больше не отказывает мгновенно: до 3 секунд ожидает завершение построения и повторяет запрос координат. Повторная попытка не использует старый трек. Обновлённые тесты проверяют патч, его повторное применение и компиляцию Java-экрана с API-заглушками. Реальная Android/C++ сборка и поездка по телефону ещё не проверены.

**Обновление в существующем GitHub-репозитории:** замените `apply_patch.py`, `overlay/app/organicmaps/routeghost/RouteGhostUi.java`, `overlay/app/organicmaps/routeghost/RouteGhostPanel.java`. Затем запустите новый workflow. Старый `Re-run jobs` без коммита файлов не обновит код.

## Исправление установки патча C++ — v2.2

Исправлена ошибка GitHub Actions `SDK Framework.cpp route geometry: expected 1 anchor, got 0`.
Вместо сопоставления большого C++-фрагмента посимвольно скрипт адресно находит
`Java_app_organicmaps_sdk_Framework_nativeGetRouteJunctionPoints` и изменяет
лишь участок получения координат, сохраняя интерполяцию и соседние JNI-методы.
Неизвестные структуры функций по-прежнему вызывают безопасную остановку сборки,
а не молчаливое применение патча. Сборка привязана к версии Organic Maps
`2026.11.11-39-android`.

**Если RouteGhost уже загружен на GitHub:** заменить **только `apply_patch.py`**
в корне репозитория и запустить **новую** сборку через Actions. Java-файлы
этим исправлением не затрагиваются.

Проверено: Python-синтаксис, применение патча два раза, несколько форм
исходного JNI-метода, сохранение соседних методов и Java-тесты на заглушках.
Реальная сборка C++/APK пока не подтверждена на GitHub Actions.


## Исправление `RouteData` (v2.3)

Если GitHub Actions выдавал `cannot find symbol RouteData` и `Plan`, теперь
`apply_patch.py` восстанавливает `RouteData.java` из встроенного исходника,
даже когда файл не попал в `overlay` при загрузке на GitHub.
До запуска тяжёлой сборки workflow проверяет наличие всех семи Java-файлов.
Для существующего репозитория достаточно заменить только `apply_patch.py`,
если остальные шесть Java-файлов уже присутствуют.
